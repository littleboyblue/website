# 什么是 Agentic AI

> 过去两年，大模型从"聊天"进化到了"干活"。但"干活"和"干活"之间，存在一个你一眼就能认出来的分水岭：模型是你在问它才答，还是它自己在想下一步该做什么。后者，就是 Agentic AI。

## 一、先别被"Agent"这个词唬住

"Agent"这个词已经快被用烂了。但凡接了个 API 的 chatbot 都敢自称 Agent，导致这个概念在 2025 年产生了严重的通货膨胀。

但 **Agentic AI** 和"套壳加个 function calling"之间有本质区别。这个区别不在能力清单上——不是"会不会调工具""有没有 memory""支不支持多轮对话"这种打勾检查。真正的区别在于一个特征：**自主规划与执行闭环**。

传统 LLM 应用的工作模式是 **Turn-based**：用户输入 → 模型输出 → 用户再输入。每一次交互都是独立决策，模型不会主动发起下一步。Agentic AI 的工作模式是 **Goal-based**：给定目标 → 模型拆解任务 → 执行 → 观察结果 → 调整计划 → 继续执行，直到目标达成或被阻断。

用个生活化的比喻：GPT-4 像一个随手可查的百科全书，你问什么它答什么，答完就下班。Agentic AI 像一个接到"帮我把下季度的市场预算方案做出来"指令的助理——它会自己去翻历史数据、找行业报告、拉竞品动态、预估各渠道 ROI，最后交给你一份完整提案，中间不会每走一步都问你"下一步我该干嘛？"

## 二、定义它，而不是描述它

给 Agentic AI 下一个相对严谨的定义：

> **Agentic AI 是一类具备自主目标感知、任务分解、工具调用、环境感知与反思修正能力的人工智能系统。它不依赖逐轮人工指令驱动，而是围绕一个高维目标自行构建并执行多步行动路径，在执行过程中动态调整策略。**

拆开来看，这里涉及四个核心能力：

**1. 目标感知（Goal Awareness）。** Agent 必须"知道自己在干什么"。给定"提高用户留存率"这样的模糊目标，它不会直接崩溃，而是会主动细化——"我先拉过去 30 天的留存漏斗数据，分析流失节点，再针对最大流失点提出方案。"它的每一步行动都可以回溯到目标本身。

**2. 任务分解（Task Decomposition）。** 人类给 Agent 的通常是结果描述，不是操作手册。Agent 需要把"分析这个代码仓库的安全性"拆成：克隆仓库 → 扫描依赖漏洞 → 检查硬编码密钥 → 审计权限配置 → 输出按风险排序的报告。这种分解能力是 Agent 和传统脚本之间最大的认知鸿沟。

**3. 工具使用与环境感知（Tool Use & Environment Awareness）。** Agent 不仅能用工具，还知道**什么时候该用什么工具**。它面对的不再是纯文本上下文，而是一个可以产生反馈的环境——API 返回了 403？那得先检查认证。文件太大被截断了？得分块读取。这种"读环境反馈并据此调整"的能力，是 Agentic AI 区别于流水线编排的关键。

**4. 反思与修正（Reflection & Self-Correction）。** 这是 Agentic AI 最被低估的能力。传统程序执行到报错就停了；Agent 会看报错信息，自己猜哪里出问题了，改完再试。Google DeepMind 的"Self-Correction is an Emergent Property"研究已经证实，足够强的模型在 Agent 框架下会自发形成纠错行为——不是被编程进去的，是涌现出来的。

## 三、Agent 的骨架：记忆、规划、行动

聊完定义，我们拉近一点看工程实现。一个典型的 Agentic AI 系统通常由三个子系统构成：

### 记忆系统（Memory）

不是"记住上一轮对话"那么简单。Agent 的记忆分三层：

- **工作记忆（Working Memory）**：当前任务的上下文窗口，类比人类的"正在想的事"。2025 年后主流模型的上下文窗口已经冲到 1M-2M tokens，但无限上下文不代表无限注意力——Agent 需要自己管理"当前窗口里放什么"，这本身就是一种记忆策略。
- **短期记忆（Short-term Memory）**：跨轮次持久化的会话状态。比如"上一轮我改了哪个文件""刚才 API 返回的 pagination token 是什么"。通常靠 session storage 或向量数据库实现。
- **长期记忆（Long-term Memory）**：跨会话的知识沉淀。用户的偏好、历史项目结构、常用的工具链——Agent 应该越用越顺手。

这三层记忆的设计，直接决定了 Agent 是"每次开工都像第一天上班"还是"越用越像你自己的员工"。

### 规划系统（Planning）

主流规划范式分两类：

**ReAct（Reasoning + Acting）**：最经典的 Agent 模式，交替进行"思考→行动→观察→思考"。简单直观，适合线性任务，但容易在长链任务中漂移。

**Plan-and-Execute**：先把完整计划列出来，再逐条执行。优势是目标始终清晰、可审计，劣势是一开始就把计划写死了，遇到意外情况需要整个推翻重来。

**树搜索 / 图规划**：2025 年后的主流方向。用 MCTS（蒙特卡洛树搜索）或图搜索在多个可能路径之间做探索-利用权衡。类似于 AlphaGo 的"模拟推演再落子"逻辑，只不过棋子变成了工具调用和子任务。

实际工程中，多数框架是混合体：顶层用 Plan-and-Execute 保持方向感，底层每个子任务用 ReAct 保持灵活性，中间插一层 reflection 做纠偏。

### 行动系统（Action / Tool Use）

这个不用多讲——调 API、读写文件、搜索、执行代码、操作浏览器。关键是**工具描述的粒度**。给太多工具，Agent 会陷入"选择瘫痪"；给太少，它能力受限。好的实践是：工具分层，按需暴露，让 Agent 自己按"技能树"逐级解锁。

## 四、Agent 不是 LLM 的升级，是范式的切换

有一个很容易混淆的地方是：Agentic AI 是不是"更强的 LLM"？不是。

LLM 解决的是**认知**问题——理解、推理、生成。Agent 解决的是**行动**问题——规划、执行、闭环。两者是正交维度。

| | 传统 LLM 应用 | Agentic AI |
|---|---|---|
| 交互模式 | 问答式，人主动 | 任务式，Agent 主动 |
| 时间跨度 | 秒级，单轮完成 | 分钟到小时级，持续执行 |
| 决策单元 | 单次推理 | 多步推理 + 环境反馈 |
| 失败处理 | 返回错误或幻觉 | 检测失败 → 反思 → 重试 |
| 人类角色 | 提问者 + 评判者 | 目标设定者 + 审核者 |
| 核心挑战 | 准确性与幻觉 | 规划质量与长程一致性 |

如果你觉得这个表里的变化看起来很眼熟，你的直觉是对的——这跟云计算从 IaaS 到 Serverless 的演进逻辑一模一样：**从"我给你配好环境你自己操作"到"我直接帮你把活干了"**。抽象层级上移了一个台阶，人的角色从操作者变成了审核者。

## 五、真正的瓶颈在"环"上

Agentic AI 听起来很完美——能规划、会反思、自主执行——但魔鬼全在"闭环"的质量上。

闭环的困难在于：**错误会复利**。一个 6 步的任务，如果每步成功率 95%，整体成功率就掉到 73%。25 步之后，不到 30%。这不是数学题，而是工程现实。

做得好的团队从不把 Agent 一放了之。常见的工程化手段包括：

**检查点（Checkpoint）**：关键步骤完成后写入状态快照，失败时从上一个检查点继续而不是从头来过。把累积失败变成局部重试。

**人工审查点（Human-in-the-loop）**：在"会产生不可逆影响"的步骤之前插一道人工确认——比如发邮件、改生产配置、触发付款。不是"AI 不行才要人审"，而是"AI 越行越要人审"。

**多 Agent 互相校验**：用一个 Agent 执行，另一个 Agent 审查。审查 Agent 只看"这一步的动作和上一步的观察之间有什么矛盾"，角色越窄越可靠。这种交叉验证的成本远低于事后救火。

**评估驱动开发（Eval-driven Development）**：不是"写完了跑两个 case 看对不对"，而是像做 benchmark 一样建一套 hundread-case 的 eval 集，包括正常路径、边界条件、恶意输入。不是一次跑一次，而是每次改 prompt 都跑一遍。Braintrust 和 Langfuse 这类工具正在把这种习惯从"最好有"变成"必须有"。

## 六、现在发生的，和将要发生的

Agentic AI 的应用场景正在从 demo 走向生产：

**工程领域**：Devin、Cursor Agent、Claude Code 已经不只是代码补全——它们自己在终端里跑命令、读报错、改代码、commit 加 push。开发者正在从"写代码的人"变成"审代码的人"。

**企业自动化**：从客服到 IT 运维，从 HR 入职到财务对账——Agent 不再回答"这个问题怎么解决"，而是直接解决这个问题。ServiceNow 和 Salesforce 的 Agent 产品线已经清晰指向这个方向。

**个人计算**：Apple Intelligence 和 Google 的 Project Mariner 都在试图让 Agent 跨 App 执行任务。"帮我把昨天收到的 PDF 发票整理到报销表里并提交"——这种横跨邮件、文件、表格的流程，正在从"当然不可能"变成"应该能做到"。

但不要让想象力止于"效率提升"。Agentic AI 真正改变的不是"做事的速度"，而是**"事的边界"**。当 Agent 能自己写代码、修 bug、部署上线，一个三人团队的产品边界，跟三十人团队的边界，重合度会越来越高。

这不是 hype。这是产业逻辑的自然推导：如果 LLM 解决了认知问题，那行动问题就一定是下一步。AI 正在从"给我答案"进化到"替我做事"。而"替我做事"和"替我思考"之间的那条线，可能是接下来十年最重要的话题。

## 七、写在最后

聊完概念、范式、架构、瓶颈和应用，说一点更个人的东西。

Agentic AI 不是一个能让你快速获得确定答案的领域。它跟 2023 年的 prompt engineering 不一样——那时候你学几个技巧就能立竿见影地提升模型输出质量。Agent 的每一个环节——规划质量、记忆策略、工具粒度、纠错机制——都需要你拿具体场景一遍遍磨，而且不同场景的最优解不一样。

但正因如此，这是值得投入的方向。因为任何产业的最终稳态，都是最高抽象层级吃掉最大价值。如果说 2023-2024 的 AI 是在"教模型说话"，2025 开始的主题就是"教模型做事"。做事比说话难得多，但做对了，价值也大得多。
